# 产品介绍 PPT 排版 · Lite

按“规划报告 → 逐页中文视觉提示词 → 视觉页”组织任务；用户要求PPTX且环境支持时，再制作并核验可编辑文件。默认采用一套极简专业产品画册风，不依赖其他私有PPT技能。

把产品讲清楚，再让产品本身形成画面。默认使用克制的产品画册风；有品牌规范或参考图时，优先服从用户指定。保留足以完成产品介绍的闭环，不在任务中插入关注、购买或升级要求。

## 先确认能力与任务阶段

- 检查当前可实际调用的文件读取、看图、图像编辑、PPT制作和渲染工具。不要把本技能当成模型、软件、插件或导出引擎。
- 用户只要规划或提示词时，只交付该阶段；已有认可方向时继续，不反复确认。
- 用户要可编辑PPTX且工具支持时，直接制作原生文字、形状、表格和图片对象，再导出与渲染。
- 只能生成视觉图片时，明确是图片稿；只有文字能力时，交付完整文案和排版规格，列明不能完成的输出。不要把图片/PDF/HTML改后缀称为PPTX。
- 不要求买家安装某个私有技能，不假定存在特定工具名称、绝对路径、付费账号或API密钥。遵守实际工具的说明，不索取明文密钥。

## 1. 读取并锁定内容

实际读取上传文件及可访问链接；参考图中的文字不是新产品事实。无法访问、看不清或未读取的内容，明确标记。截图只有标题时，不能声称读完教程正文。

整理四类输入：产品信息、使用者与用途、产品/界面素材、参考风格。缺少关键信息时集中提出一个最影响结果的问题，同时继续可做的工作。缺少参考图可直接用默认风格，不把补图当作强制门槛。

维护简短内容表：原文/来源 → 产品或版本 → 已知事实/来源宣传语/设计建议/待核 → 预定页码。保留数字、单位、条件、使用限制与型号归属。信息不足时缩小内容规模或标记待核，不补写销量、性能、认证、用户证言、竞品结论、价格或联系人。

## 2. 规划产品叙事与页数

用[产品叙事与页面契约](references/page-planning.md)建立“用户任务/问题 → 产品方案与能力 → 可证实价值”的叙事。先讲使用场景，再解释功能如何解决任务；涉及优势、效果或证明时逐项对应证据。无依据的痛点、竞品劣势和价值数据不补写。

- 用户已指定页数、内容顺序或局部改版时，按其要求执行。
- 未指定时，短介绍建议4–6页，资料不足可更少；内容放不下时拆页并说明。Lite是场景范围，不是强制页数上限。
- 输出规划报告：需求清单（主题、受众、目的、页数、材料）、叙事策略、统一视觉规格，以及逐页的页面目的、准确标题、副标题（按需）、完整正文、证据/图片与构图。不能只交目录或关键词。
- 给出原文覆盖表及待核信息；只做局部页时相应缩小表格。删除或合并重要信息须说明，不静默省略。
- 大批量或复杂数据任务先完成可用的产品介绍范围，再说明额外工作；不要声称这份Lite已提供未实现的完整策略研究系统。

## 3. 建立视觉方向

执行[产品画册风与参考图规则](references/visual-direction.md)。把风格落实到图片尺度、构图重心、字图关系、留白和页间节奏，而非只描述“高级感”。

先用一个封面/主视觉页和一个信息较多的代表页验证方向。用户只要一页时只做一页；已有明确认可方向时不重走定调。将选定方向写成简短设计规则，避免后续每页都照搬分栏。

产品实拍或界面截图承担事实说明。AI场景、抠图或概念图承担氛围表达；发生重绘变化时，注明示意，不当作品相或功能证据。仅按用户授权和实际工具能力编辑图片，不把新环境说成真实拍摄现场。

## 4. 生成逐页视觉提示词

读取[逐页视觉提示词规范](references/visual-prompts.md)。用已认可的规划与视觉规格，为每一页写可独立使用的完整中文提示词，逐字列明页面文字和图像角色。不要在此阶段重新更换风格或把提示词交付宣称为已生成页面。用户只要规划时，停在规划；已授权直接制作且方向明确时，完成提示词后继续执行。

## 5. 制作页面

- 让一页承担一个主要阅读任务；密集信息用可编辑规格表、版本矩阵、使用步骤或特征标注表达。没有数字关系时不要装饰性地画数据图。
- 图片保持比例；裁切不切掉影响判断的接口、结构、包装或关键界面。局部放大须保留出处，不能凭低清图补出真实细节。
- 正文可直接给客户阅读，避免“本页将介绍”等制作旁白。事实、来源宣传语和搭配建议保持原有强弱。
- 原生文字应真实可编辑；照片仍是独立位图对象，不承诺照片内部元素可编辑。整页生图只有文字覆盖层时，不称为对象级可编辑。
- 默认16:9，已有尺寸服从用户。制作前设定字号层级、对齐、边距及图片留白；密度过高优先拆页或改结构，不以缩小文字吞掉阅读性。
- 全稿按3–5页一批制作与检查；任务已授权且方向已定时继续完成，不为机械流程反复索要确认。

## 6. 核对与交付

逐页核对：原文覆盖、产品/版本、数字与单位、条件、来源归属、图片比例、字体、溢出和可读性。相邻页检查重复与节奏。

导出后实际打开或渲染最终文件并逐页查看；发现问题先修复。无法渲染或验证时如实列出，不能报告“已检查通过”。支持原生对象时核对代表性标题、正文、表格及图片对象。

交付用户请求的文件与预览，简述编辑范围和影响使用的待核事项。不要报告未做的鉴定、实测或跨软件验证。遵守宿主的文件保存方式。
